\section{Introduction}

\subsection{About}

This document gives an in-depth explanation of how to use the software
Traffic Simulator.
The software is written in Java 17 and was developed as a project for the
course System- och programvaruutveckling (DT117G) at Örebro University.

\subsection{Overview}

Traffic Simulator is a software for simulating traffic scenarios,
of which there are several to choose from (scenarios are called maps in
Traffic Simulator). The simulator features a visual representation of
the simulation, to let the user review things like traffic flow in
"real time", that is, as the simulation runs.

The simulation can be sped up/down, paused, stopped or
reset at any time.
Additionally, Traffic Simulator has settings for configuring different
simulation parameters before the simulation starts. These include settings
for traffic inflow, the preferred speed of vehicles and for some maps, the
length of the road.

Useful statistics are shown during the simulation. These are updated in
"real time" and include the current number of vehicles in the simulation,
average speed and inflow/outflow of vehicles.
When the simulation is stopped, a statistics summary is presented, with
the option to export to a CSV file for further processing.

There is also an option to run simulations without visuals. Instead, 
the statistics summary is shown as soon as the host computer has finished
the simulation. This can be useful to run multiple simulations quickly
and compare their statistics after the fact.

\subsection{Simulation Engine}

Traffic Simulator uses a simulation model based on the Nagel-Schreckenberg
model. This uses discrete time, and hence the simulation moves in
\textbf{steps} or \textbf{ticks}.

Roads are divided into discrete cells, and every car in the
simulation moves zero or more cells each tick. Each car has a preferred
speed, and tries to move accordingly. The preferred speed is randomised
at spawn time
for each car between the min and max values as set in the settings menu.

To make the simulator behave like traffic, each car looks ahead and adjusts
its speed accordingly: if no obstacle (including other vehicles) is seen,
the car tries to keep its preferred speed, otherwise it slows down
or stops to avoid collisions.

The scale of the model translates to the real world as follows:

\begin{itemize}
    \item One cell represents 7.5 m (meters), as proposed by the
        Nagel-Schreckenberg model.
    \item One tick represents 2.7 s (seconds).
    \item A speed of 1 cell/tick then corresponds to 10 km/h in the
        real world.
\end{itemize}

\subsection{Playback Controls}

These are the controls available when running a simulation
with visuals.

\begin{center}
    \includegraphics[width=\textwidth]{images/transport.png}
\end{center}

\begin{enumerate}
    \item[] Top to bottom, left to right:
    \item \textbf{Time scaling} can be adjusted while the simulation is
        running. This will speed up/slow down the simulation; that
        is, the simulated time will run fast or slower.
        \textit{Tip: pressing + or - on the computer's keyboard
        will increment/decrement this control!}
    \item \textbf{Pause}/\textbf{Resume} the simulation (and the visuals).
        \textit{Tip: The simulation can also be paused using the
        space bar key!}
    \item \textbf{Reset} simulation. This will abort the running simulation
        and start a new one with the same settings (even if paused).
        \textit{Tip: The simulation can also be reset using the
         backspace key!}
    \item \textbf{Stop} the simulation and show statistics summary.
        \textit{Tip: The simulation can also be stopped using the
        escape key!}
\end{enumerate}

\subsection{Offline Simulation}

Traffic Simulator allows for running simulations without any visuals. This
is much faster than running simulations in "real time", and can be
useful for running very long simulations or multiple simulations quickly.
The statistics summary is still shown and the results can be exported to
a CSV file.

When running a simulation in offline mode, the graphical interface shows a
progress bar and a button for cancelling the simulation.

    \includegraphics[height=2.5cm]{images/spawn-chance.png}

\section{Statistics Page}

When a simulation is stopped (or completed/cancelled if run in
offline mode), a summary of the simulation statistics is shown.

\subsection{Statistics Summary}

The statistics summary shows a summary of the simulation and is
similar to the live statistics discussed in section \ref{live_stats}
(page \pageref{live_stats}), but with a few differences:

\begin{center}
    \includegraphics[width=\textwidth]{images/final-stats.png}
\end{center}

\textbf{Total cars exited} is shown, and refers to the number
of cars that have exited the simulation by driving out of the
simulated area. \pag

\textbf{Average speed}, \textbf{InFlow} and \textbf{OutFlow} now
shows the average for the whole simulation. \pag

\textbf{Peak traffic} is the maximum number of current cars
(cars simultaneously inside the simulation) at any one time during
the simulation. \pag

\textbf{Runtime} is the total (real world) time for which the simulation
was running. Unlike simulated time, this is not affected by time
scaling and is also shown after running a simulation in offline mode. \pag

Also, the \textbf{settings} used for the simulation are shown.

\subsection{Navigation Buttons}

From the statistics summary, the user can either exit the program or
return to the menu for running another simulation. There is also
an option to export the statistics summary to a CSV file.

\begin{center}
    \includegraphics[width=\textwidth]{images/report-btns.png}
\end{center}

\begin{enumerate}
    \item \textbf{Back to Menu} shows the settings menu, where a new simulation
        can be started.
    \item \textbf{Export to CSV} lets the simulation statistics summary be
        exported
        to a CSV file, for further processing or importing to a spreadsheet.
    \item \textbf{Exit} program to desktop.
\end{enumerate}

statistics summary of a simulation after it has run. This can then
be imported into a spreadsheet program or data analysis software
for comparing multiple simulations with slightly different settings,
